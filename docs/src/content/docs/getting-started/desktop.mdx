title: Desktop installation
description: Install full macOS, Windows, or Linux bundles and understand their runtime requirements.

Desktop Sim Bridge is a client for an existing bridge. Create the bridge on an Android
gateway first, then pair the desktop with its relay URL and 52-character recovery code.
There is no desktop SIM gateway or camera pairing.

## Get the right download

Download from the [latest release](https://github.com/rennerdo30/sim-bridge/releases/latest)
or the [homepage](https://sim-bridge.renner.dev/#download).

| Target | Download | Notes |
| --- | --- | --- |
| macOS Apple silicon | `Sim-Bridge-<version>-macos-arm64.zip` | Developer ID signed and notarized |
| macOS Intel | `Sim-Bridge-<version>-macos-x86_64.zip` | Developer ID signed and notarized |
| Windows x64 | `Sim-Bridge-<version>-windows-x64-setup.exe` | Installer; recommended |
| Windows x64 | `Sim-Bridge-<version>-windows-x64.zip` | Portable, no installation |
| Linux x64 | `Sim-Bridge-<version>-linux-x64.zip` | Portable bundle |

Each release lists the SHA-256 of every file in `SHA256SUMS.txt`.

## macOS

The minimum target is macOS 12.0. Unzip the download and move **Sim Bridge** to
Applications. The app is signed with a Developer ID and notarized by Apple, so it opens
without a security warning.

Credential storage uses the login Keychain. Local-network access is needed for relay
discovery; local notifications depend on OS permission. The app retains native menus
and window controls. Closing the last window quits it; minimizing or Hide keeps the
process available to sync.

## Windows

Run `Sim-Bridge-<version>-windows-x64-setup.exe`. It installs Sim Bridge for your Windows
account only, so no administrator rights are needed, adds a Start menu entry and appears in
**Settings → Apps** for uninstalling. Your pairing and settings stay when you update or
uninstall. The installer is not yet code-signed, so SmartScreen may ask you to confirm it
once (**More info → Run anyway**).

For the portable zip, extract the **entire** archive and start `sim_bridge.exe` from that
folder. Keep the DLLs and the `data/` folder next to it.

The source build needs Visual Studio's **Desktop development with C++**, the Windows
SDK, and C++ ATL libraries. These are build requirements, not a requirement to install
Visual Studio on every client computer. The installer is built with NSIS from
`app/windows/installer/sim-bridge.nsi`.

## Linux

Unzip the download without flattening its folders and start `./sim_bridge` from it. Runtime services have distinct responsibilities:

| Requirement | Purpose |
| --- | --- |
| GTK3 and `libsecret-1-0` | Native UI and secure-storage integration |
| Running, unlocked Secret Service on session D-Bus | Store and restore bridge credentials |
| Desktop notification service | Show local notifications |
| `avahi-daemon` on system D-Bus | Discover LAN relays |

If Avahi is unavailable, enter the relay URL manually. This does **not** remove the
Secret Service requirement for credentials. On headless systems or minimal window
managers, configure an appropriate session service rather than assuming a keyring exists.

The bundle includes a `.desktop` file and icon under `share/`. Distribution packaging
can install them in the standard application/icon directories and make `sim_bridge`
available on `PATH`. A portable bundle alone does not register a system launcher.

## Updates

Sim Bridge checks the latest release once a day while it runs; turn this off or use
**Check now** under **Settings → Updates**. Only stable releases of this project are offered,
and every download is verified against the release's checksums before it is used.

- **Windows:** **Install and restart** downloads the installer, closes Sim Bridge, installs
  the update and starts it again.
- **macOS and Linux:** **Download** saves the verified new version in your Downloads folder.
  Quit Sim Bridge and replace it with the new version.

## Sync and clipboard behavior

Keep the app open or minimized. Desktop clients receive relay change events while the process is running;
there is no tray process, login-start service, or desktop APNs/FCM wake-up.

Automatic copying of verification codes defaults off on desktop. Enable it in Settings
only if you want incoming codes to replace the clipboard. On macOS, sensitive copies
use advisory transient/concealed markers and are cleared after three minutes if the
clipboard still contains that copy. Windows and Linux use the standard clipboard.
Copied data is available to other apps and clipboard tools on the same computer.

## Build from source

Use the matching operating system and its native toolchain. From `app/`:

```sh
flutter pub get --enforce-lockfile
flutter build macos --release
# On Windows: flutter build windows --release
# On Linux:   flutter build linux --release
```

For the complete prerequisites and isolated smoke test, see
[development](/docs/guides/development/).
